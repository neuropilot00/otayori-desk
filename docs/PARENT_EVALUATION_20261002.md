# おたより desk — 32명 가상 학부모 평가 및 실서버 검증

평가일: 2026-10-02 · 앱 버전: `a128467fb8ddd2405dfc26df86e8179747c6def4` · [실서버](https://otayori-web-production.up.railway.app/)

## 결론과 확인된 문제

**상용 출시 준비 완료로 판정하지 않는다.** 학교·학년 필터와 학동 자료의 정직한 범위 표시는 개선됐지만, 학부모가 항목별 요약만 믿고 준비하거나 외국어로 공지 내용을 읽는 핵심 흐름에는 미완료 사항이 있다. 이번 평가는 이를 발견·검증한 것으로, 아래 두 기능 문제를 수정한 배포는 아니다.

### P1 — 준비물의 선택 조건이 항목별 표시에서 잘린다

- 재현: 桜野小学校 → 1年生 → 学校 → 1年生 学年だより・10月号를 연다.
- API의 보호자 안내 목록 8번째 줄은 `長ぐつ`, 9번째 줄은 `(はきたい人だけ、学校で長ぐつにはきかえます。)`이다. UI는 각 분류를 첫 8줄로 자른다. 따라서 장화는 희망자만이라는 조건이 짧은 분류 목록에서 빠진다.
- 준비물 목록에는 티셔츠와 사육통 안내의 문장 조각도 존재한다. 줄마다 키워드를 분류해 문맥이 갈리고, 다시 표시 개수가 제한되는 구조다.
- 전체 일본어 원문과 공식 PDF 링크에는 조건이 남아 있다. 문서 전체가 소실된 것은 아니지만, 분류 목록을 독립적인 준비물 체크리스트로 신뢰할 수 없다.
- 근거: `web/app.js:643`, `sakurano_line_notifier/formatter.py:44`, `live-api-evidence.json`.
- 수정 기준: 줄 단위가 아니라 완결된 문장/문단과 조건을 묶고, 생략 시 의미가 바뀌지 않도록 표시한다. 희망자만·해당자만·후일 안내·금지 조건이 본문과 함께 유지되는 회귀 테스트가 필요하다. 전체 내용을 무조건 길게 펼치는 해결은 피한다.

### P1 — 외국어 화면은 있지만 공지 본문 번역은 제공되지 않는다

- 한국어 선택 시 메뉴·범주·날짜 표현은 바뀌지만 10월호 제목, 준비물 문장, 본문과 추출 주의문은 일본어 그대로였다. 본문 번역 제어도 찾지 못했다.
- 공통 상세 렌더러는 언어에 관계없이 `notice.title`과 `notice.text`를 일본어로 표시한다. 영어·중국어에서도 일본어 제목을 확인했다.
- 근거: `web/app.js:648`, `web/app.js:653`, `web/app.js:655`, 실서버 한국어 상세 화면.
- 수정 기준: 원문과 명확히 구분된 한국어·영어·중국어 본문 번역, 날짜·필수/선택 조건 보존, 번역 실패 시 정직한 원문 전환이 필요하다. 메뉴 현지화만으로 이 요구사항을 충족했다고 보지 않는다.

### P2 — 실제 학동 생활연락은 여전히 수집하지 않는다

- 실서버는 `daily_notice_status=not_collected`를 반환한다. 학동 일일 일정·픽업·준비물·보호자 연락을 제공하는 기능은 없다.
- 사쿠라노 범위에는 아소베에 공개 편지 1건(본문 미확인)과 입회·시설·제도 참고자료 11건이 있다. 아소베에와 학동 생활연락은 다른 자료다.
- `学童の生活連絡：未収集`와 설명을 실제 모바일 화면에서 확인했다. 참고자료는 기본 접힘이며 최신 공지·푸시와 분리된다.
- 이 표시는 올바른 한계 고지이지, 수집 자체를 완성한 것은 아니다. 비공개 보호자 메시지를 권한 없이 수집하는 해결은 금지한다.

### 검증 공백 — 실제 휴대폰 푸시 도착

- 표시 조건과 저장된 알림 조건이 별도로 보이고, 표시 필터를 바꿔도 알림 조건은 바뀌지 않는다고 안내한다. 동의 전 등록 버튼은 비활성이다.
- 동의·등록·해제·시험 알림을 실행하지 않았다. iOS/Android 실제 수신, 백그라운드, 지연, 권한 거부/복구는 이번 평가에서 통과 판정을 내릴 수 없다.
- 자동화 테스트 통과와 실제 휴대폰 수신은 다른 검증이다. 새 동의 없이 알림 대상을 자동 변경하는 방식으로 해결하지 않는다.

## MiroFish 실행 범위

[공식 MiroFish](https://github.com/666ghj/MiroFish)의 Reddit 시뮬레이션 실행기와 IPC 인터뷰를 실제로 사용했다. 브라우저 검증은 별도로 수행해 사실 자료로 제공했다. 가상 학부모가 브라우저를 직접 조작한 것은 아니다.

- 가상 보호자 32명: 일본어 20명, 한국어·영어·중국어 각 4명. 모두 의도적으로 구성한 합성 인물이며 실제 가족 정보는 없다.
- 학년 1–6, 진학, 맞벌이/교대근무, 다자녀·다른 학교, 학동/아소베에, 조부모, 작은 화면, 디지털 숙련도와 보호자 간 분담 상황을 나눴다. 일본 학부모 인구를 대표하는 표본은 아니다.
- 소셜 2라운드: 첫 라운드 댓글 32건, 다음 라운드 추가 행동 없음 32건. **64개의 서로 다른 의견이 나온 것으로 세지 않는다.** 환경의 refresh 기록은 의견이 아니다.
- 최종 개별 인터뷰 32/32건. 각 응답의 인물 ID, 필수 필드와 OASIS 데이터베이스의 interview trace를 대조했다.
- 유효 모델 호출 96건. 제출은 재시도 포함 97건이며, 지연 요청 090과 재시도 097의 입력이 같음을 검증하고 재시도 응답만 결과에 사용했다. 초기 연결 실패/중단 실행은 평가에서 제외·보존했다.
- 실제 생성 모델: `gpt-6-astra`, medium. 설정의 `gpt-4o-mini`는 호환 프로토콜 표기일 뿐 생성 모델이 아니다.
- MiroFish 커밋 `7657031ac01184afe2cb220f5ee3545573b5e843`; OASIS 0.2.5 / CAMEL 0.2.78.
- Zep 그래프 구축, 자동 인물 생성, Twitter 동시 실행, MiroFish ReportAgent는 사용하지 않았다. 이 문서는 실제 응답과 실검증 증거를 종합한 별도 보고서다.

초기 사실 자료의 “본문 번역 옵션이 존재한다”는 문구는 실검증 결과와 달라, **모든 개별 인터뷰 전에 F8–F10 정정 자료를 제공했다.** 최종 해석은 정정 후 인터뷰를 사용한다. 알려준 결함에 의견이 집중되는 유도 효과와 동일 모델의 응답 유사성을 인정한다. 32명의 동의를 시장 검증, 실제 만족도, 성공률이나 독립적인 32번의 버그 발견으로 제시하지 않는다.

## 실제 학부모 베타에서 확인할 과제

1. 도움 없이 자녀의 학교·학년을 선택하고 10월호를 찾아, 활동일·우천 예비일·장화가 선택인지 근거와 함께 답하게 한다.
2. 한국어/영어/중국어 보호자가 준비물과 조건을 이해해 공동 보호자에게 전달할 수 있는지 관찰한다. 현재는 본문 번역 미제공을 먼저 고지한다.
3. 학동 이용자가 내일 준비물·픽업을 어디에서 확인해야 하는지 알아내고, 미수집 상태를 “공지 없음”으로 오해하지 않는지 확인한다.
4. 다자녀 보호자가 표시 조건과 저장된 알림 조건을 각각 확인한다. 실제 기기 알림 실험은 자발적 동의를 받아 별도로 한다.
5. 성공 여부·도움 필요 여부·오해한 지점·실측 소요시간을 기록한다. 아동 이름이나 비공개 공지 내용은 수집하지 않는다. 현재는 실사용 수치가 없다.

## 증거와 재검증

로컬 평가 폴더에 `manifest.json`, `results.json`, `simulation-trace.json`, `model-receipts.json`, `live-api-evidence.json`, 입력 프로필·질문·정정 자료와 세 장의 390px 실서버 스크린샷을 보존했다. `control.py collect`는 32개 인터뷰와 실행 trace를 다시 대조하며 데이터 해시를 기록한다. 실패 실행은 성공 수에 섞지 않았다.
